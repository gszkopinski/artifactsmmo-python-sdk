# AGENTS.md

## Introduction
This document outlines the strategy for using AI agents to enhance the development and maintenance of the **artifactsmmo-sdk** project. The goal is to leverage AI agents for tasks such as **automated testing**, **code generation**, **documentation**, and **refactoring**, without integrating the LLM directly into the project.

---

## Use Cases

### 1. **Automated Testing**
- **Task**: Generate and maintain test cases for new or updated API endpoints.
- **Implementation**:
  - Use agents to analyze the existing test suite (unit tests in `tests/`, live tests in `tests/live/`) and identify gaps.
  - Automatically generate tests for new endpoints based on schema definitions (e.g., `src/artifactsmmo_sdk/models/actions.py`, `src/artifactsmmo_sdk/models/characters.py`).
  - Unit tests mock the HTTP layer with **pytest-mock** (`mocker`), never `unittest`. Use the `client` and `respond` fixtures from `tests/conftest.py`; `tests/test_modules.py` holds one entry per endpoint (verb + path).
  - Live tests (`tests/live/`, marker `live`) hit the real API and only run with `pytest -m live` and `TOKEN`/`API_URL` set.
  - Example: Use agent to create tests for new `TaskRewardSchema` or `BankItemSchema` endpoints.

### 2. **Code Generation**
- **Task**: Update or generate code to align with the new API specifications.
- **Implementation**:
  - Use agents to parse schema files (e.g., `src/artifactsmmo_sdk/models/actions.py`, `src/artifactsmmo_sdk/models/characters.py`) and generate corresponding client code in `src/artifactsmmo_sdk/actions/actions.py` or `src/artifactsmmo_sdk/characters/characters.py`.
  - Example: If the API introduces a new `TaskRewardSchema`, an agent can generate the necessary client methods in `actions.py`.

### 3. **Documentation**
- **Task**: Automatically generate or update documentation based on code changes.
- **Implementation**:
  - Use agents to parse schema and model files (e.g., `src/artifactsmmo_sdk/models/common.py`, `src/artifactsmmo_sdk/models/grand_exchange.py`) and generate API documentation in Markdown or reST format.
  - Example: Generate documentation for new `TaskRewardSchema` and `BankItemSchema` in the `README.md` or a dedicated `docs/` directory.

### 4. **Refactoring**
- **Task**: Improve code structure and maintainability by refactoring existing code.
- **Implementation**:
  - Request, error mapping, timeout and 429 retry are centralised in `src/artifactsmmo_sdk/base.py` (`BaseModule._request`, `COMMON_ERRORS`, `build_session`). New endpoints must use `_request` and only declare their endpoint-specific error codes.
  - Example: Cooldowns are only reported (HTTP 499 -> "Character in cooldown."), there is no waiting logic yet; a `handle_cooldown` helper would belong in `base.py`.

---

## Integration

### Tools and Dependencies
- **pytest**: For running and maintaining test cases generated by agents.
- **pydantic**: For schema validation and code generation.
- **pre-commit**, **ruff** and **mypy**: Code quality, formatting and typing (`uv run ruff check . && uv run mypy src`). CI (`.github/workflows/ci.yml`) runs them with the unit tests.

### Workflow
1. **Analyze**: Use agents to analyze the codebase and identify areas for improvement.
2. **Generate**: Use agents to generate new code or tests based on schema definitions.
3. **Validate**: Run tests using `pytest` to ensure generated code works as expected.
4. **Refactor**: Use agents to refactor code for better maintainability and performance.

---

## Best Practices

- **Modular Design**: Keep generated code modular to avoid tight coupling between components.
- **Version Control**: Use Git to track changes made by agents and review them before merging.
- **Testing**: Always validate generated code with a comprehensive test suite.
- **Documentation**: Keep documentation up-to-date with code changes, using agent-generated content where appropriate.

## Examples

### Example 1: Generating Tests
**Input**: New `TaskRewardSchema` in `src/artifactsmmo_sdk/models/actions.py`
**Agent Output**: New entry in `tests/test_modules.py` for the corresponding endpoint.

### Example 2: Code Generation
**Input**: Schema for `BankItemSchema` in `src/artifactsmmo_sdk/models/actions.py`
**Agent Output**: New method in `src/artifactsmmo_sdk/actions/actions.py` built on `self._request(...)`.

### Example 3: Refactoring
**Input**: Repeated `try/except HTTPError` blocks in a module
**Agent Output**: The module methods rewritten on top of `BaseModule._request` (see `src/artifactsmmo_sdk/base.py`).

---

## Project Structure
- **Main Client**: `src/artifactsmmo_sdk/client.py` builds the shared session and initializes modules like `Account`, `Actions`, `Characters`, etc. (`grand_exchange` is not wired yet).
- **Modules**: Each module (e.g., `src/artifactsmmo_sdk/actions/actions.py`, `src/artifactsmmo_sdk/characters/characters.py`) handles specific API endpoints.
- **Tests**: Unit tests in `tests/` (`test_base.py`, `test_modules.py`), live tests in `tests/live/`, run with pytest.
- **Models**: Data models and enums (e.g., `SlotEnum` in `src/artifactsmmo_sdk/models/actions.py`) are used for schema validation and type hints.

---

## Conclusion
By leveraging AI agents for **automated testing**, **code generation**, **documentation**, and **refactoring**, the **artifactsmmo-sdk** project can be modernized and maintained efficiently without relying on the LLM. This approach ensures the SDK remains aligned with the latest API specifications and improves developer productivity.
